# CycleTracker development

## Product style

The owner wants a minimal, practical tool, similar in tone to SteroidPlotter.

- Use plain headings: Today, Plan, Plotter, History, Health.
- Write labels, short instructions, validation errors and useful model limitations.
- Do not add slogans, promotional copy, motivational text, aspirational headings, decorative captions, reassuring filler or brand-story panels.
- Empty states should state what is missing and the available action.
- Do not add text merely to fill space. Prefer fewer panels and controls that directly support the task.
- Preserve this direction throughout future development.

## Engineering

- Keep original personal records, credentials, database files and local mail out of this public repository.
- Use the shared schedule and simulation packages rather than screen-specific calculations.
- Scientific capability labels must follow inspected evidence. Numerical tests alone do not establish human predictive validity.
- Preserve drafts on failed saves and conflicts. Actual administrations retain snapshots.
- Run type checking, domain/API tests and relevant browser checks before publishing changes.
- Report build/test evidence separately from Git publication, container startup and live deployment.
